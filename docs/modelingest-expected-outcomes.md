## 一、典型使用场景与预期产出

### 场景 1：技术文档知识库（最常见）

**用户投入**：
```bash
# 准备工作：收集 PDF 技术文档到一个文件夹
./tech_docs/
├── python_tutorial.pdf       (150页)
├── machine_learning.pdf      (300页)
├── system_design.pdf         (200页)
└── api_reference.pdf         (80页)

# 执行命令（5分钟）
modelingest build \
  --source ./tech_docs \
  --output ./tech_kb \
  --visual \
  --distill

```

│   ├── 函数定义与调用.md
│   ├── 类与对象.md
│   └── 装饰器原理.md
│
├── 机器学习/

## 六、风险与限制

### 6.1 技术限制

| 限制项 | 影响 | 缓解措施 |
|-------|------|---------|
| 视觉模型推理慢 | 处理速度降低 30% | 批量处理 + GPU 加速 |
| 截图占用空间大 | 1000页 = ~1.5GB | 可选压缩 / 低分辨率模式 |
| 复杂布局识别错误 | ~10% 页面解析失败 | 人工审核 + 反馈优化 |
| LLM API 成本 | 蒸馏阶段 $0.1-0.5/千页 | 支持本地 Ollama 模型 |

### 6.2 内容限制

| 限制项 | 影响 | 建议 |
|-------|------|------|
| 手写笔记 | OCR 准确率 ~80% | 使用打印文档 |
| 扫描 PDF（低质量） | 截图模糊 | 提供高质量原件 |
| 加密/保护 PDF | 无法处理 | 先解密 |
| 动态网页（需登录） | 爬取失败 | 手动下载后处理 |

### 6.3 使用限制

| 场景 | 不适用原因 | 替代方案 |
|------|-----------|---------|
| 实时协作编辑 | 非协作工具 | 配合 Obsidian Sync |
| 极大规模（>100GB） | 处理时间长 | 分批处理 |
| 视频内容为主 | 不处理视频 | 先提取字幕/截图 |
